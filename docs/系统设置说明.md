# 系统设置说明

## 一、会话看板与 AI 简报

**路径：** 管理后台 → 左侧 **「会话看板」**（仪表盘也有快捷入口）

### 顶部指标口径（鼠标悬停卡片 ⓘ 可看全文）

| 展示名 | 含义 | 删除会话后 |
|--------|------|------------|
| **窗口消息** | 统计窗口内所有消息条数，且所属会话在库中仍存在 | 该会话及其消息立即不计入 |
| **活跃会话** | 窗口内至少有一条消息的去重会话数（现存） | 同上 |
| **新建会话** | 按 `sessions.created_at` 在窗口内计数，含未发言的「空会话」 | 管理端硬删除后减少；用户端本地删对话**不影响** |
| **空会话** | 新建会话中，窗口内没有用户消息的个数 | 同上 |
| **新建会话深度** | 仅针对窗口内**新建**的会话：平均/峰值消息条数 | 已删会话不参与 |

**「新建会话 12」** 表示最近 N 天内创建了 12 条会话记录，**不是**删掉的聊天条数。

### AI 简报

1. 选择统计天数（7 / 14 / 30 天）后点击 **「生成 AI 简报」**（需 **AI 模型** Tab 已配置）
2. 生成成功后 **滚动到页面最底部** 「AI 会话简报」区域；内容为 **Markdown 排版**（标题、列表），非原始 `##` 符号
3. 简报会 **按天数保存最新一份**（`admin_ai_reports`），切换 Tab 或刷新页面后 **自动恢复** 同窗口天数的上一份
4. 简报要求模型仅依据统计 JSON 与首句样本作答，无法推断时会写「数据不足」
5. 页面中部 **数据摘要** 为纯数字归纳，不调用 AI

**Token 记录：** **Token 明细** → `admin_chatboard_brief`（会话看板简报）。

**数据分析 / Token 监管：** 同上持久化与 Markdown 展示；类型分别为 `admin_analytics_insights`、`admin_token_analyze`。

**商城 AI：** 商品「AI 自动生成」「AI 批量优化」「单条 AI 优化」为异步任务。进入商城管理会自动恢复进行中的任务进度弹窗；弹窗展示当前阶段、步骤百分比、执行日志与已运行时间；超过 5 分钟无更新的任务会自动结束，也可在弹窗内「取消任务」。同一时间仅允许一个商城 AI 任务（`admin_jobs` 表）。

### Token 明细（全站 AI 消耗）

**路径：** 管理后台 → **Token 明细**

| Tab | 用途 |
|-----|------|
| 总览 | 总请求、输入/输出 Token、用户消费、AI 参考成本、盈亏 |
| 功能覆盖 | 已登记 AI 功能是否在计费表/模型日志出现 |
| 全部流水 | 计费明细 + 模型日志合并（去重） |
| 消费记录 | 每条记录的输入、输出、费用、倍率 |
| AI 监管 | 全站 Token 趋势 AI 报告（`admin_token_analyze`） |

**管理端 AI 功能类型（节选）：** 数据分析 AI `admin_analytics_insights`、知识库 AI `admin_knowledge_ai`、会话看板简报、Prompt 测试、运营中心辅助等。新增功能须在 `server/ai/usageRegistry.js` 登记并调用 `trackAIUsage`。

**数据分析页：** 管理后台 → **数据分析** →「生成 AI 洞察」→ 类型 `admin_analytics_insights`。

**知识库：** 编辑案例弹窗 → 先填写或「从当前会话加载」**案例材料** →「AI 根据材料填写」生成标题/行业/成功要点；类型 `admin_knowledge_ai`（记入 Token 明细）。无材料时不会调用 AI。

## 二、系统设置各 Tab 建议保留什么？

| Tab | 建议 | 说明 |
|-----|------|------|
| **基本设置** | 保留 | 站点名、欢迎语、公告、是否启用聊天 |
| **AI 配置** | 仅保留参数 | **API Key 请在「AI 模型」Tab 配置**；此处主要改温度、计费倍率、新用户赠送余额 |
| **充值设置** | 保留 | 开关、档位、最低金额、**手动收款二维码 URL**（无在线支付时必配） |
| **微信支付** | 按需 | 开通 Native 在线支付时填写；见下方支付说明 |
| **支付宝** | 按需 | 开通电脑网站支付时填写 |
| **安全设置** | 保留 | 修改管理员密码 |
| **闲管家** | 按需 | 使用闲鱼/订单同步时配置 AppKey、Secret |

**不必在「AI 配置」里填 API Key：** 已迁移到 **AI 模型** 面板，避免重复且无效。

## 三、支付要准备什么？（不是上传 zip，是密钥文本）

本系统 **充值** 支持两种模式：

1. **手动模式（默认）：** 用户在「充值设置」里的微信/支付宝 **收款二维码** 转账，管理员在 **充值管理** 里确认到账。无需商户 API。
2. **在线支付：** 在 **微信支付 / 支付宝** Tab 填齐参数并 **打开启用开关 → 保存**，用户端会出现对应支付通道。

### 微信支付（APIv3 · Native 扫码）

| 配置项 | 从哪里获取 |
|--------|------------|
| 商户号 `wx_mch_id` | 微信支付商户平台 → 账户信息 |
| AppID `wx_app_id` | 关联的公众号/小程序/开放平台 |
| APIv3 密钥 `wx_api_v3_key` | 商户平台 → API 安全 |
| 证书序列号 `wx_serial_no` | API 证书页 |
| 商户私钥 `wx_private_key` | 下载的 `apiclient_key.pem` **全文粘贴**，或填服务器上的 **文件路径** |
| 回调 `wx_notify_url` | `https://你的域名/api/payment/wechat/notify` |

**额外（server/.env）：** `WECHAT_PAY_CERT_PATH` = 微信支付 **平台证书** 文件路径（用于回调验签，不在后台表单里）。

### 支付宝（电脑网站支付）

| 配置项 | 从哪里获取 |
|--------|------------|
| AppID `ali_app_id` | 开放平台应用 |
| 应用私钥 `ali_private_key` | 本地生成的 RSA2 私钥 PEM，**粘贴全文** |
| 支付宝公钥 `ali_public_key` | 上传应用公钥后，平台提供的 **支付宝公钥**（非应用公钥） |
| 异步通知 `ali_notify_url` | `https://你的域名/api/payment/alipay/notify` |
| 同步跳转 `ali_return_url` | 支付完成后的展示页 |

**说明：** 支付宝一般 **不需要** 单独上传证书文件到服务器，私钥/公钥在后台多行框粘贴即可。

## 四、保存后是否生效？

- **系统配置 / 支付配置：** 保存后立即写入数据库；支付配置会 **自动热加载**，无需重启 PM2。
- 支付 Tab 顶部显示 **「已就绪，用户端可见」** 表示在线通道已开通。
- 若仅用手动二维码充值，支付开关保持 **关闭** 即可。
