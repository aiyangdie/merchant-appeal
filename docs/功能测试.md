**生产入口：** `server/index.js`（默认端口 `3003`，PM2 进程名 `merchant-appeal`）  
**前端：** `npm run dev` / 构建产物 `dist/`

## 1. 项目检查结论（2026-05-19）

### 1.1 已修复（本次）

大文件拆分后，部分 **动态 `import()` 相对路径** 仍指向旧目录（`routes/prod/` 下的 `./opsCenter.js` 等），会在**首次命中该代码路径时**才报错。已统一改为 `../../` 或 `../`：

| 文件 | 问题 | 修复 |
|------|------|------|
| `server/routes/prod/adminRoutes.js` | `opsCenter`、`tokenOversightHints`、`db` 路径错误 | → `../../opsCenter.js` 等 |
| `server/routes/prod/sessionRoutes.js` | 申诉文案流式 `llm.js` 路径错误 | → `../../ai/core/llm.js` |
| `server/handlers/chatStreamHandler.js` | `appealGuideSnapshot`、`promptLoader` 路径错误 | → `../ai/...`、`../prompts/...` |
| `server/handlers/deepAnalysisHandler.js` | `knowledgeBase`、`localAI` 路径错误 | → `../knowledgeBase.js` 等 |

### 1.2 仍存在的风险 / 技术债

| 类别 | 说明 | 建议 |
|------|------|------|
| **大文件** | `server/db.js`（~2300 行）、`adminRoutes.js`（~1950 行）未继续拆分 | 按 `docs/ARCHITECTURE-SPLIT.md` 分阶段拆 DAO / admin 子路由 |
| **自动化测试** | 仅 JWT、策略生成等 5 个单测；路由/API 无集成测试 | 逐步为会话、流式聊天、管理端 ops 补测 |
| **废弃代码** | `server/app.js`、`server/routes/*` 生产不挂载，易误改 | 仅参考 `server/routes/prod/*` |
| **登录安全** | 用户侧手机号快捷登录、无密码；管理端需改默认弱口令 | 见 `SECURITY-AUDIT.md`、`FIX-GAPS-ROADMAP.md` SEC-1 |
| **AI 依赖** | 流式聊天、深度分析、申诉文案依赖外部模型与余额 | 测试前确认 `.env` 中模型 Key、用户余额 |
| **支付回调** | 微信/支付宝/ePay 等 notify 需公网与签名校验 | 本地仅测「创建订单 + 人工确认」路径 |

### 1.3 健康检查（每次发版前）

```bash
cd /root/我的项目/merchant-appeal
node --check server/index.js
npm test
node scripts/smoke-api.mjs http://127.0.0.1:3003
```

期望：语法检查通过；Jest 2 套件全绿；冒烟 3 项均为 `OK 200`。

## 2. 测试环境准备

| 项 | 要求 |
|----|------|
| Node | ≥ 18（项目使用 ESM） |
| MySQL | 与 `.env` 中 `DB_*` 一致，库已初始化 |
| 服务 | `npm run start` 或 `pm2 restart merchant-appeal` |
| 前端 | `npm run dev`（Vite 代理到 3003）或访问已构建 `dist/` |
| 测试账号 | 普通用户（手机号注册/登录）；管理员（`/api/admin/login`） |
| 工具 | 浏览器开发者工具；可选 `curl` / Postman |

**获取用户 Token：** `POST /api/user/login` → 响应 `token`，后续请求头：

```http
Authorization: Bearer <token>
```

**获取管理员 Token：** `POST /api/admin/login` → `token`，同上。

## 4. 用户端功能测试

### 4.1 注册与登录

| 编号 | 步骤 | 期望 |
|------|------|------|
| U-01 | `POST /api/user/register` 合法手机号 | 201/200，返回用户信息与 token |
| U-02 | 重复注册同一手机号 | 合理错误提示 |
| U-03 | `POST /api/user/login` 已注册手机号 | 200，token 有效 |
| U-04 | `GET /api/user/:id` 带 token | 200，仅能访问本人 |
| U-05 | `GET /api/user/:id` 无 token 或他人 id | 401/403 |

### 4.2 会话生命周期

| 编号 | 步骤 | 期望 |
|------|------|------|
| S-10 | `POST /api/sessions` 创建会话 | 返回 `sessionId` |
| S-11 | `GET /api/user/:id/sessions` | 列表含新会话 |
| S-12 | `GET /api/sessions/:id/messages` | 200，含欢迎/系统消息 |
| S-13 | `GET /api/sessions/:id/info` | 200，展示收集字段与完成度 |
| S-14 | `PUT /api/sessions/:id/field` 更新单字段 | 200，info 中字段已更新 |
| S-15 | `GET /api/sessions/:id/field-history` | 200，有变更记录 |
| S-16 | 用错误 `sessionId` 访问上述接口 | 404 或 403（非本人） |

### 4.3 AI 对话（核心）

| 编号 | 步骤 | 期望 |
|------|------|------|
| C-01 | `POST /api/chat/stream`，`sessionId` + 用户消息 | SSE：`start` → 增量 `delta` → `done` |
| C-02 | 对话中观察右侧/接口 `info` 字段收集 | 行业、违规原因等逐步写入 |
| C-03 | 信息不足时继续对话 | 出现「还缺」类 hint（SSE 或 UI） |
| C-04 | 中途关闭页面/断开 SSE | 不应异常扣费（审计项，见 FIX-GAPS） |
| C-05 | 余额不足时发消息 | 明确错误，不静默失败 |

### 4.4 分析与申诉产出

| 编号 | 步骤 | 期望 |
|------|------|------|
| A-01 | `GET /api/sessions/:id/deep-analysis` | 数据足够时返回分析；不足时 `reason` |
| A-02 | `GET /api/sessions/:id/deep-analysis-result` | 与深度分析结果一致 |
| A-03 | `GET /api/sessions/:id/analysis` | 本地策略/风险摘要 |
| A-04 | `POST /api/sessions/:id/generate-appeal-text` | SSE 或 JSON 返回申诉正文 |
| A-05 | `GET /api/sessions/:id/appeal-text` | 可读取已生成文案 |
| A-06 | `GET /api/sessions/:id/appeal-guide` | 申诉指导结构完整 |
| A-07 | `POST /api/sessions/:id/appeal-guide/generate` | 可触发生成/刷新 |
| A-08 | `PUT /api/sessions/:id/appeal-progress` 更新进度 | 再次 GET 进度一致 |
| A-09 | `POST /api/sessions/:id/appeal-feedback` 提交结果反馈 | 200，用于学习闭环 |

### 4.5 投诉文书与文案

## 8. 常见问题排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `Cannot find module './opsCenter.js'` | 动态 import 路径未修复 | 确认使用 `routes/prod` 下 `../../` 路径 |
| SSE 立即断开 | 未带 token、sessionId 无效 | 检查 Authorization 与会话归属 |
| 管理端 ops 全 500 | MySQL 连接或 opsCenter 查询异常 | 查服务端日志、`DB_*` 配置 |
| AI 无回复 | 模型 Key、余额、限流 | `.env`、`GET /api/user/:id/usage` |
| 前端 404 API | 代理未指向 3003 或仍引用旧 `server/routes` | Vite proxy / 仅 `registerProdRoutes` |
