## 1. 设计理念与愿景

### 1.1 产品调性

**核心关键词**: 专业、可信赖、高效、智能化

**设计风格**: 商务科技风（Professional Tech）

**视觉基调**:
- 简洁大气，注重信息层次
- 专业但不冰冷，融入适当亲和感
- 数据可视化清晰直观
- 移动端优先考虑触控友好性

### 1.2 目标用户特征

| 用户类型 | 特征 | 设计考量 |
|---------|------|---------|
| 管理员/运营人员 | 长时间在电脑前操作 | 降低视觉疲劳、信息密度适中 |
| 客户（移动端） | 焦虑、急于解决问题 | 操作步骤少、反馈即时、流程清晰 |
| 艾阳老板 | 需要快速掌握后台 | 重要信息突出、操作直观 |

### 1.3 设计目标

- **易用性**: 新用户5分钟内能理解核心操作
- **效率**: 常用操作3步内完成
- **信任感**: 专业视觉传达可靠服务
- **一致性**: 全平台体验统一

### 2.6 动效系统

#### 动效原则

```
1. 自然流畅 - 使用 ease-out 或 ease-in-out 曲线
2. 快速响应 - 交互反馈 < 100ms
3. 适度克制 - 避免过度动画分散注意力
4. 有意义 - 动效传达状态变化，不是装饰
```

#### 动效时长

```
duration scale
──────────────────────────────────────────────────
instant    50ms    - 状态切换（复选框、开关）
fast       100ms   - 微交互（hover、点击反馈）
normal     200ms   - 标准过渡（展开、收起）
slow       300ms   - 页面元素进入
slower     500ms   - 大区块动画、模态框
```

#### 缓动函数

```
ease-out      cubic-bezier(0, 0, 0.2, 1)   - 元素进入、展开
ease-in       cubic-bezier(0.4, 0, 1, 1)   - 元素退出、收起
ease-in-out   cubic-bezier(0.4, 0, 0.2, 1) - 来回切换
spring        cubic-bezier(0.175, 0.885, 0.32, 1.275) - 弹性效果
```

#### 典型动效场景

| 场景 | 动效类型 | 时长 | 缓动 |
|-----|---------|------|------|
| 按钮点击 | scale(0.98) + opacity | 100ms | ease-out |
| 卡片hover | translateY(-2px) + shadow | 200ms | ease-out |
| 弹窗出现 | scale(0.95->1) + opacity | 300ms | spring |
| 菜单展开 | height + opacity | 200ms | ease-in-out |
| 页面切换 | fade + slide | 300ms | ease-out |
| 加载状态 | pulse / skeleton | 1.5s循环 | ease-in-out |
| 成功反馈 | scale(1->1.1->1) | 300ms | spring |

## 6. 响应式设计规范

### 6.1 断点定义

```
响应式断点 (Breakpoints)
──────────────────────────────────────────────────
移动端     < 768px    - 手机竖屏
平板       768px+     - 平板、手机横屏
桌面端     1024px+    - 小桌面
大桌面     1280px+    - 标准桌面
超大桌面   1536px+    - 大屏显示器
```

### 6.2 移动端适配原则

```
移动端设计原则
──────────────────────────────────────────────────

1. 优先级内容
   - 核心操作按钮放大（最小44px触控区域）
   - 重要信息放前面，次要信息折叠
   - 单列布局，避免横向滚动

2. 导航适配
   - 顶部导航栏固定
   - 底部标签栏用于主要功能切换
   - 汉堡菜单用于次要功能

3. 列表适配
   - 表格转为卡片列表
   - 减少列表列数
   - 重要信息放前面

4. 表单适配
   - 输入框全宽
   - 日期选择器使用原生picker
   - 图片上传支持拍照

5. 图表适配
   - 简化图表，小屏幕显示核心数据
   - 支持左右滑动查看更多
```

### 6.3 触控交互

```
触控交互规范
──────────────────────────────────────────────────

触控区域
├── 最小触控区域: 44px × 44px
├── 按钮最小高度: 44px
├── 列表项最小高度: 48px
└── 间距: 元素之间至少8px

手势支持
├── 点击: 单指tap
├── 长按: 触发上下文菜单
├── 滑动: 列表左右滑动（删除等操作）
├── 下拉刷新: 列表页、详情页
└── 上拉加载: 列表分页

避免的交互
├── Hover状态（移动端无hover）
├── 双击
├── 鼠标悬停展开
└── 需要精确定位的交互
```

## 10. 与前端开发的协作规范

### 10.1 协作流程

```
设计-开发协作流程
──────────────────────────────────────────────────

1. 设计评审
   └── 设计稿完成后，产品经理 + 前端开发 + 后端开发评审

2. 设计交接
   ├── 提供设计稿链接
   ├── 提供设计规范文档
   └── 提供组件库文件

3. 实现确认
   ├── 前端开发实现组件
   ├── 设计验收设计稿实现
   └── 不符合及时沟通

4. 迭代优化
   ├── 开发中发现问题及时反馈
   └── 设计优化及时更新设计稿
```

### 10.2 沟通要点

```
协作沟通要点
──────────────────────────────────────────────────

需要明确的要点:
1. 组件是否需要复用
2. 动态数据如何展示（列表为空、加载中、加载失败等）
3. 交互细节（点击后跳转还是展开、是否需要加载状态等）
4. 极端情况处理（文字过长、数量过多等）
5. 动画实现细节（时长、缓动、触发条件）
```
